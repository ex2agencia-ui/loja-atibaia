**`parseBRDate` final** (aceita `DD/MM/YYYY` e `DD-MM-YYYY`):
```typescript
function parseBRDate(value: string | null | undefined): Date | null {
  if (!value) return null
  const match = value.trim().match(/^(\d{2})[\/\-](\d{2})[\/\-](\d{4})$/)
  if (!match) return null
  const [, day, month, year] = match
  return new Date(Number(year), Number(month) - 1, Number(day), 12, 0, 0)
}
```

### Check-in por QR Code (implementado completo)

**Schema** — campos adicionados em `LojaSession`:
```prisma
checkInToken  String?  @unique
checkInAberto Boolean  @default(false)
```
Migration rodada em produção via `scripts/add-checkin-fields.mjs`.

**Fluxo completo:**
1. Admin cria sessão → `checkInToken` (UUID) gerado automaticamente no POST
2. Página da sessão: botão abre `CheckinModal` com QR Code + data da sessão
3. Botão imprimir: abre janela standalone com HTML+SVG (não `window.print()`)
4. Toggle abre/fecha check-in via `PATCH /api/sessoes/[id]`
5. Card de quórum conta presenças `P` e atualiza a cada 10s
6. Membro acessa `/checkin` no celular, toca "Escanear QR Code"
7. `html5-qrcode` abre câmera traseira e lê o QR
8. Sistema extrai token, chama `GET /api/checkin/[token]` e `POST` (registra presença)
9. Estados: confirmado / já registrado / encerrado / erro

## Contexto técnico importante

### Next.js 16.2.4 com Turbopack
- Sem `middleware.ts` — proteção em cada route/page via `auth()`
- `searchParams` é `Promise<{...}>` — sempre `await searchParams`

### Neon HTTP serverless
- **Nunca**: `createMany`, `updateMany`, `deleteMany`, `create({ include })`, `$transaction()`
- **Sempre**: operações individuais com `Promise.all([...items.map(i => prisma.model.create(...))])`

### html5-qrcode — dynamic import obrigatório
```typescript
const QrScanner = dynamic(
  () => import("@/components/checkin/qr-scanner").then(m => m.QrScanner),
  { ssr: false }
)
```
Sem `{ ssr: false }` quebra no build (módulo acessa `window`/DOM).

### qrcode.react v4 — sem asChild
```tsx
<QRCodeSVG value={url} size={256} />
// DialogTrigger: usar render prop, não asChild
<DialogTrigger render={<Button>...</Button>} />
```

### Auth pattern em client components
`useSession()` requer `SessionProvider` acima na árvore. O dashboard layout agora provê isso via `<SessionProvider session={session}>`. Preferir props passadas do server component pai quando possível — usar `useSession()` apenas quando não há outra forma.
